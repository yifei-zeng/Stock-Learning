> v1 的问题：只是「删掉口水话的逐字稿」，没有结构，10 分钟的篇尚可，40 分钟的篇是一堵墙。

## 二、目标形态（模板）

```
<头部：标题 / UP主 / 链接 / 时长 / 一句话结论>

## 30 秒速读          ← 3~5 条，读完能复述整篇
## 名词表              ← 本篇术语先解释再出现
## 目录                ← 分节导航，带时间戳
────────────────────────────────
## 一、<小节标题>（MM:SS~MM:SS）
<段落，一段讲完一个完整意思（长短不限），句末带时间戳>

### 要点
- **<可执行规则>**（稿 MM:SS）
- <数字/阈值>（稿 MM:SS）
...
────────────────────────────────
## 待确认项
## 校正记录              ← 全部移到这里，正文里一句不留
```

## 三、七条硬规范

**1. 分节，按「意思」断段，不按字数断段**
按内容切 4~8 个大节，每节 `## 标题（MM:SS~MM:SS）`。节内不再用时间戳当标题。

> **⚠️ 2026-10-04 主人拍板：段长不设上限，500 字也没关系——内容完整优先于篇幅。**
> （原为「80~200 字，超过就拆」，是我 2026-10-03 自己定的，主人从未要求；今天明确废止。）

**断段的唯一依据是「一段讲完一个完整意思」**：意思断了就分段，意思没说完就别拆。
- ⛔ **绝不为了压字数把一个完整的论述／案例／推导切成两半**——这是旧标准最有害的副作用
- ✅ 短句独立成段完全可以，不必凑到某个字数
- ✅ 一个案例、一组数据、一条完整规则，该多长就多长
（若非要看长度，**必须用字符口径**，见第六节；字节口径虚高 2.1 倍，曾害我把合规段落全切碎。）

**2. 时间戳降级为句末标记**
v1 是每段开头 `[MM:SS]`；v2 改成**句末** `（稿 MM:SS）`，只在有结论价值的句子后标。
一节 3~5 个时间戳即可，不必句句标——**这是「人读」和「可查」的分层**。

**3. 校正痕迹全部移出正文（硬性）**
正文里**禁止**出现「（原稿"xxx"）」「（存疑）」「（音）」。
- 已在正文改正的 → 静默改，只在文末校正记录里留一行
- 不确定要不要改的 → **正文保留原词 + `〔?〕` 上标**，文末统一解释
- 段落里塞不下的疑似 → 整条进「待确认项」

**4. 每节末尾挂「要点」**
`- **可执行结论**（稿 MM:SS）`，是本节能拿去用的东西。**要点是给人抄进交易规则的**，不是复述正文。

**5. 术语必须先解释**
第一次出现写成：`三班组（指某类短线操盘资金，UP主未展开）`；后文直接用简称。
跨篇复用术语（如「炸板六原则」在 03 篇讲过）要标注 `→ 见 03 篇`。

**6. 头部一句话结论**
看完头部就知道这篇值不值得读、解决什么问题。附 `## 30 秒速读`。

**7. 不改观点、不补充**
只重排、去冗、提层、校正。**不许把原文没有的推论写进去**——这仍是学习材料，不是投资建议。

## 四、什么时候该派子代理

批量重做按 README 第四节第 4 条：shell 只跑统计，N 个并行子代理每个 2~3 篇，
只回传「路径 ｜ 字数变化 ｜ 要点数 ｜ 待确认项数」，正文不进主上下文。

**子代理 prompt 必须写全上面七条 + 给一篇 v2 样例**（只给结构样例，不给正文内容，
避免它抄 11 篇的术语）。产出后主代理抽检 2~3 篇，重点查：**分节数、有无巨型块（>1000 字）、有无残留校正痕迹**。
⚠️ **不要派子代理去"拆长段"**——段长不是验收项，让它拆只会破坏完整论述（2026-10-04 主人拍板）。

## 六、段长统计：只用于排查「巨型块」，不再是验收项（口径必须用字符）

**macOS 自带 awk 的 `length()` 按字节算，不做多字节感知。** 中文一字 3 字节，
所以 `awk 'length($0)>200'` 实际只相当于「67 字」，会报出 824 处假超标，
我据此差点让子代理把已合规的段落全部切碎（01 篇已有 37/71 段不足 80 字，再拆就低于下限了）。

三个子代理独立发现了这个问题并拒绝盲从，拦对了。**这条坑记在这里，别再犯。**

实测对照（同一行）：

| 口径 | 值 |
|---|---|
| `wc -m`（字符） | **199** ✅ |
| `wc -c` / `awk length`（字节） | 427 ❌ 虚高 2.1 倍 |
| `gawk` | 本机未安装 |

> **2026-10-04 起这条不再是验收项**（主人：超 200 无所谓，500 字也没关系，内容完整优先）。
> 保留这一节有两个理由：① 排查 **>1000 字的巨型块**（几个意思揉一起，该拆）；② **字符口径这条坑仍然成立**——
> 用字节口径会虚高 2.1 倍，会把正常段落误判成"超长"从而去拆段，那正是主人不想要的破坏。

**排查巨型块的命令（唯一可信口径）：**

> ⚠️ 2026-10-04 修：旧版写的是 `glob.glob('*.txt')`，但**三库精简版已于 2026-10-03 全部转成 `.md`**，
> 照抄旧命令会匹配到 **0 个文件 → 静默输出空结果 → 误判"全部合规"**。现在改成 `.md`，并强制打印文件数。

```bash
cd /Users/yifei/Desktop/股海悟道/来去由心/逐字稿/1-精简版-人读
/Users/yifei/.workbuddy/binaries/python/versions/3.13.12/bin/python3 -c "
import re, glob
fs = sorted(glob.glob('*.md'))
print('统计文件数:', len(fs), '← 为 0 说明路径/后缀错了，结果无效')
for f in fs:
    inbody=False; lens=[]
    for l in open(f,encoding='utf-8'):
        s=l.strip()
        if re.match(r'^##\s*[一二三四五六七八九十]', s): inbody=True; continue
        if s.startswith('##') or s.startswith('###'): inbody=False; continue
        if inbody and s and not s.startswith(('-','|','>','*','#')): lens.append(len(s))
    giant=[x for x in lens if x>1000]; chip=[x for x in lens if x<20]
    print(f'{f}|段{len(lens)}|最长{max(lens) if lens else 0}|巨型块>1000:{len(giant)}|碎句<20:{len(chip)}')
"
```
> 只看 `巨型块` 与 `碎句` 两列即可，**"最长"那一列不必干预**。

**统计范围约定**（⚠️ 差一条就得出完全不同的结论）：
只算 `## 一、`~`## 十、` 大节内的**正文散段**；
`### 要点`、`## 30 秒速读`、`## 名词表`、`## 目录`、表格、代码块、`## 待确认项`、`## 校正记录`、`## 时效性内容隔离区` **都不计入**。

### ⚠️ 两轮统计不一致的根因（2026-10-04 实测，别再踩）

**`### 要点` 很容易被误当成正文计进去**，原因很阴：`startswith('## ')` 对 `###` 返回 **False**（第三个字符是 `#` 不是空格），
所以只写 `if s.startswith('## '): inbody=False` 的话，**`### 要点` 及其下面整段列表会被当成正文**，
而一个要点块合并后可能上千字——于是"超 200 的段"凭空多出来。

实测对照（同两篇文件，四种口径，结论可以差一个数量级）：

| 口径 | 03-题材炒作周期2.0 | 04-讲透基金怎么买 |
|---|---|---|
| **A 字符 + 仅大节正文散段（✅ 唯一可信）** | 31 段，最长 **199**，超 200：**0** | 25 段，最长 **200**，超 200：**0** |
| B 字符 + 把 `### 要点` 块也算进去 | 38 段，最长 344，超 200：7 | 33 段，最长 280，超 200：4 |
| C 字符 + 全文所有块（含名词表/目录/待确认） | 44 段，最长 1042，超 200：9 | 39 段，最长 1026，超 200：6 |
| D **字节**口径（`awk length` / `wc -c`） | 38 段**全超**（中文虚高 2.1 倍） | 33 段**全超** |

> 这张表里的"超 200"计数**已成历史**（2026-10-04 起不再是验收项），留着是当**口径陷阱的证据**：
> 同一对文件，换个口径能从 0 变成"全超"。**排查巨型块时只用 A 口径**，其余三种都会造假象。

## 七、⚠️ 写完总结/精简版必须校验时间戳引用（2026-10-03 踩坑）

**光写不算完，必须回到逐字稿核对每个「稿 MM:SS」是否真的有那句内容。**

15 篇那次凭印象写了引用，31 处里**1 处落空**（写「稿 16:41」，实际内容起于 16:47），
另有一处「稿 20:43」引错了整行——那行是梯队列举，不是板位分段定义。
**肉眼扫不出来，因为格式完全合法、时间戳格式完全正确。**

### 校验命令（求差集，只看落空的）

```bash
cd /Users/yifei/Desktop/股海悟道/巨拳
/Users/yifei/.workbuddy/binaries/python/envs/default/bin/python - <<'PY'
import re
def secs(p):                      # 同时吃 MM:SS 与 H:MM:SS
    p=[int(x) for x in p]
    return p[-2]*60+p[-1] if len(p)==2 else p[0]*3600+p[1]*60+p[2]
doc=open('视频总结/15-全市场的手法大全.md',encoding='utf-8').read()
src=open('逐字稿/2-完整逐字稿/15-全市场的手法大全.逐字稿.txt',encoding='utf-8').read()
have={secs([x for x in m.groups() if x]) for m in re.finditer(r'\[(?:(\d+):)?(\d{1,2}):(\d\d)\]',src)}
cited={secs([x for x in m.group(1).split(':') if x!='']) for m in re.finditer(r'稿\s*([\d:]+)',doc)}
bad=sorted(c for c in cited if c not in have)
print('逐字稿 %d 个时间戳，最晚 %d 分；文档引用 %d 处'%(len(have),max(have)//60,len(cited)))
print('落空:',['%d:%02d'%(c//60,c%60) for c in bad] if bad else '无（全部命中）')
PY
```

> ⚠️ **2026-10-04 修：旧正则 `\[(\d+):(\d+)\]` 解析不了「超过 1 小时」的时间戳。**
> 60 分钟以上的视频会写成 `1:00:12`／`稿 1:07:23`，旧正则把 `1:00:12` 读成 **0 分 12 秒**，
> 后果：① 逐字稿被当成"只覆盖到 59:59"；② **60 分钟之后的引用全部误判为落空**。
> 实测 `逻辑哥复盘笔记/04-核心方法分享2.0进阶版/03-题材炒作周期2.0`（**视频总长 1:09:03**）正是这种情况。
> **判据**：校验报「引用时间 > 视频总长」时，先看那个值是不是正好等于视频总长（如 `1:09:03`）——
> 是的话属于**脚本文本解析错**，不是引用写错，别去改文档。
