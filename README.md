## 五、视频总结标准工作流程（SOP）

主人丢来 B 站视频链接（单个或批量）时，**严格按以下五个步骤执行**，每一步的输入、输出、格式规范都已写死，保证可重复。总览：

```
B站链接 → ①登记归档 → ②提取原始逐字稿（版本一） → ③清洗出精简版（版本二）
        → ④生成结构化总结 → ⑤同步操作模式文档 → 回写该UP主索引
```

### 步骤 ① 接收链接与登记归档

- **输入**：B 站视频链接（完整链接 / `b23.tv` 短链 / 裸 BV 号均可），单个或一批
- **处理**：
  1. 确认 UP 主归属：对照第一节的 UP 主表 → 归入 `逻辑哥复盘笔记/` 或 `来去由心/`；**是新 UP 主先问主人**要不要开新目录，不要自作主张
  2. 分配序号：该 UP 主目录内已有最大序号 +1；一次多篇按主人给链接的顺序排
  3. 批量（≥3 个链接）时，先输出一张待处理清单给主人确认，再动手
- **输出**：待处理清单，格式 `链接 ｜ UP主 ｜ 归属目录 ｜ 序号 ｜ 暂定主题`

### 步骤 ② 提取视频逐字稿（版本一：原始转录）

- **输入**：待处理清单中的链接 + 归属目录
- **命令**：

  ```bash
  python3 工具/bili_transcript.py "<链接或BV号>" --out "<UP主目录>/逐字稿/2-完整逐字稿"
  ```

  SESSDATA 自动从 `~/.bili_sessdata` 读取；报 `-403` 即过期，请主人重新取（Chrome 登录 bilibili → F12 → Application → Cookies → www.bilibili.com → SESSDATA）
- **验收**：看脚本打印——中文轨道存在、时长覆盖率 ≥70%（不足会打 ⚠，需人工核对）；外语轨已被自动跳过。无字幕视频转本地 whisper 方案（见技能 `bilibili-video-summary` 的踩坑记录）
- **重命名**（脚本输出的 `<标题>.ai-zh.txt` / `<标题>.conclusion.json` → 标准命名）：
  - `<标题>.ai-zh.txt` → `NN-主题.逐字稿.txt`
  - `<标题>.conclusion.json` → `NN-主题.AI文稿.json`
- **输出（版本一）**：`<UP主>/逐字稿/2-完整逐字稿/NN-主题.逐字稿.txt` —— **未经修改的原始转录内容**。格式：头部四行（视频标题 / UP主 / 链接 / 时长）+ 分隔线 + `[MM:SS] 一句话` 的逐句转录。**此文件定稿后只读，任何后续环节不得改动它**（存疑回查都靠它）

### 步骤 ③ 清洗逐字稿（版本二：可阅读精简版）

- **输入**：版本一（`NN-主题.逐字稿.txt`）
- **清洗规则**：
  1. **保留** `[MM:SS]` 时间戳（步骤 ④⑤ 的出处标注全靠它）
  2. **删除**：开场寒暄、求关注点赞、口语填充词（嗯/啊/呃/好吧/对不对/对吧/就是说等）、同义重复、无信息过渡句、**一切非中文内容**（英文夹杂、乱码、无意义字符）
  3. **保留**：全部与股票操作相关的实质信息——观点、判断依据、规则、数字、案例、图形与盘口描述
  4. **合并碎句**：同话题连续短句合并为通顺段落，**不得改写观点、不得补充原文没有的内容**
  5. **术语校正**：按已知错字表（风尘比=封单比、遂原/随缘=燧原、木希=沐曦、B刃=壁仞、养鸡=养基）；**不确定的一律保留原文并标「（存疑）」，不许猜**
- **输出（版本二）**：`<UP主>/逐字稿/1-精简版-人读/NN-主题.精简版.txt` —— 整理、分段、去冗余后的可阅读文本。格式规范：
  - 头部：保留版本一的标题 / UP主 / 链接
  - 正文：按话题分段，每段一个主题，段内保留时间戳
  - 文末：`## 校正记录`，逐条列 `原词 → 校正词（时间戳）`；无校正写"无"

### 步骤 ④ 生成结构化视频总结

- **输入**：版本二（主依据）；版本一（存疑处回查原文）；`NN-主题.AI文稿.json`（参考官方大纲分段，不作内容依据）
- **固定结构**（七个小标题，顺序不变）：

  ```
  # NN · 主题
  > 来源/链接/时长/逐字稿与精简版路径 + 实例时点声明
  ## 核心观点
  ## 行情判断
  ## 操作逻辑（选股·买点·卖点）
  ## 关键规则与数字
  ## 案例分析
  ## 待确认项
  （文末）仅作个人学习梳理，不构成投资建议
  ```

- **硬性规范**：
  1. **每条结论标注出处**，格式 `（稿 MM:SS）`，指向版本二时间戳
  2. 盘面实例必须注明"实例为视频录制时点的个案，可复用的是方法而非结论"
  3. 表述含糊、数字矛盾、与他篇冲突的 → 进「待确认项」，注明原文+时间戳，**不臆造、不发挥**
  4. 遵循第六节行为准则：不给投资建议、校正必标注
- **输出**：`<UP主>/视频总结/NN-主题.md`；**回写该 UP 主的索引文件**（`00-索引.md` / `00-合集索引.md`）
- **批量执行**：单篇可直接做；≥3 篇按第四节第 4 条派并行子代理（每个 2~3 篇，步骤 ③④ 由同一子代理完成，只回传「路径 ｜ 字数变化 ｜ 一句话结论 ≤50字 ｜ 待确认项数」），主代理只做核对和写索引

### 步骤 ⑤ 同步更新操作模式文档

- **输入**：步骤 ④ 产出的新总结 + `我的复盘/操作模式提炼-龙头战法.md`（活文档，允许迭代，但每次更新必须留痕）
- **更新规则**：
  1. 新视频提出了**文档里没有的规则** → 补入对应模块（选股/买点/卖点/仓位/止损止盈/复盘清单），必须带来源标注 `（UP主NN·稿 MM:SS）`
  2. 新视频**强化或补充了已有规则** → 只补出处和量化细节，不重复写规则
  3. 与现有规则**冲突**：**不预设"以谁为准"，哪个更有道理用哪个**。按第七节的判定标准裁决（可量化 > 定性、有作废条件 > 没有、层级不同就叠加不硬选、事前 > 事后、匹配账户规模与看盘时间、判不出来先按更严的），**裁决理由必须写在条目后面**；确实判不出的进文档的「待确认项」
  4. 新视频中无法判定的表述 → 进文档「待确认项」，不自行发挥
  5. 文档头部的"待确认项"被主人确认后 → 回填规则正文，从待确认项中移除
- **输出**：更新后的操作模式文档，文末追加一行更新记录：`日期 ｜ 新增篇目 ｜ 新增/修订规则数 ｜ 新增待确认项数`

## 六、行为准则（别踩线）

1. **不做投资建议。** UP 主在每篇视频里都声明"仅作为个人梳理，不作为投资建议"。你同样不能给具体买卖标的、点位、仓位的建议。帮主人建立他自己的规则，而不是替他决策。
2. **不要脑补。** 逐字稿是语音识别产物，术语错字很多（如"风尘比"=封单比、"遂原/随缘"=燧原、"木希"=沐曦、"B刃"=壁仞、"养鸡"=养基）。写总结时校正后**必须标注做了哪些校正**，识别不清的如实写"不确定"。
3. **视频里的具体判断会失效。** 那些 2026 年 9 月的盘面实例、时间窗口预测（如"看到 2027 年年中"）是 UP 主个人推演，不是结论。**真正可复用的是方法论框架**（模板、清单、流程），提醒主人区分这两者。
4. **不删主人的复盘记录。** `我的复盘/` 下的文件只增不改，除非主人明确要求。

## 七、已知坑（技术层面）

| 坑 | 表现 | 处理 |
|---|---|---|
| AI 文稿接口要 wbi 签名 | 只带 SESSDATA 调接口一律 `-403` | 脚本已实现签名，别改成裸请求 |
| 必须签名的字幕接口 | 未签名版会**轮换返回别的视频的字幕**（实测拿到过完全无关的内容） | 脚本用的是 `/x/player/wbi/v2`，别改回 `/x/player/v2` |
| cookie 要两个 | 只有 SESSDATA 时字幕列表常为空 | 脚本自动从 `/x/frontend/finger/spi` 取 buvid3 |
| 中文轨道判断 | B站轨道名是 `ai-zh`，不能用 `startswith("zh")` 匹配，否则会挑错语言 | 已修复，改脚本时注意 |
| 长视频多语言轨 | 一个视频可能有 6~8 条语言轨，挑错会浪费大量 token | 脚本按"时长覆盖率 + 中文优先"自动挑，会打印每条轨道的首句供核对 |
